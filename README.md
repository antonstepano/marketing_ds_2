# Предсказание покупки интернет-магазина за 90 дней

ML-проект по техническому заданию «Маркетинг»: оценить вероятность того, что клиент совершит покупку в следующие 90 дней. Основная метрика — **ROC-AUC**. Выполнен полный цикл исследования данных, разработки признаков, сравнения моделей и финального тестирования.

## Структура

- `Predskazanie_pokupki_90_dnei.ipynb` — **основной воспроизводимый ноутбук**, с кодом, выполненными графиками и отдельными выводами Markdown **после каждого этапа и подэтапа**.
- `requirements.txt` — зависимости.
- `.gitignore` — исключения для Git.
- `results/metrics.json` — итоговые численные показатели и сравнение моделей.
- `results/purchase_model.joblib` — обученная модель с перечнем признаков и порогом, дополнительный артефакт. Не загружайте файлы joblib от непроверенных авторов.

**Исходные CSV не включены в репозиторий** из-за объёма и возможных ограничений на распространение данных.

## Данные

Положите исходный архив `Предсказание покупки (DS_2)-20261104T181157Z-1-001.zip` **в папку с ноутбуком**. Распаковывать не нужно. Также поддерживаются распакованные CSV в `filtered_data/` или `data/filtered_data/`. Ноутбук читает:

- `apparel-target_binary.csv` — 49 849 клиентов и бинарная целевая переменная;
- `apparel-purchases.csv` — 202 208 товарных строк;
- `apparel-messages.csv` — 12 739 798 действий с рассылками;
- `full_campaign_daily_event.csv` и `full_campaign_daily_event_channel.csv` — агрегаты кампаний, используемые для анализа (без утечки будущих дат).

Оригинальный ZIP весит около **172 МБ** и не подходит для стандартной загрузки одним файлом в GitHub (лимит GitHub — 100 МБ на обычный файл). Не добавляйте датасет в обычный Git. Его публикация также требует разрешения владельца данных.

## Запуск

Поддерживается Python **3.10+** с совместимыми версиями зависимостей. В текущем исполнении использовались Pandas 2.2.3, NumPy 2.3.5, scikit-learn 1.8.0, CatBoost 1.2.8, LightGBM 4.6.0.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
jupyter lab
```

Откройте `Predskazanie_pokupki_90_dnei.ipynb`, выберите ядро Python и выполните **Run All**. Оригинальные данные читаются из ZIP напрямую; большая таблица рассылок обрабатывается частями по 400 000 строк. После обучения создаётся папка `outputs/` с моделью, метриками и скорингом отложенных клиентов.

## Методика

1. Анализ целевой переменной и дисбаланса классов, пропусков и повторяющихся товарных позиций.
2. EDA: **гистограммы, boxplot**, временная динамика продаж, категории товаров, взаимодействия с рассылками, связь поведения с целевой переменной.
3. Исторические признаки клиента: покупки и траты за 30/90/180/365 дней, Recency/Frequency/Monetary, межпокупочные интервалы, категории, send/open/click/purchase и доли каналов.
4. Стратифицированное разделение **70% / 15% / 15%** по `client_id`. Подбор модели и порога только на валидации.
5. Сравнение Dummy, LogisticRegression, HistGradientBoosting, LightGBM и CatBoost. Для моделей со встроенной остановкой по quality используется валидационная выборка. Затем обучение победителя на train+validation и единственная оценка на test.
6. Интерпретация модели и маркетинговая метрика `Recall@Top10%`.

**Предупреждение по временной утечке:** история покупок заканчивается **2024-02-16**, история индивидуальных рассылок — **2024-02-15**, а глобальные кампании продолжаются до **2024-05-15**. Рабочая дата отсечения признаков — 2024-02-16; будущие события глобальных кампаний исключены из модели. **Точная дата формирования целевой переменной в ТЗ не названа**, поэтому её надо подтвердить перед продуктивным запуском. Данная оценка на holdout клиентах не заменяет *out-of-time* тест.

**Повторы покупок:** 73 020 совпадающих строк не удаляются автоматически, поскольку без уникального ID позиции заказа повтор может представлять собой реально приобретённые одинаковые товары.

## Результаты проверенного прогона

| Модель | ROC-AUC на validation |
|---|---:|
| Dummy | 0.5000 |
| LogisticRegression | 0.7314 |
| HistGradientBoosting | 0.7468 |
| LightGBM | 0.7461 |
| CatBoost depth=5 | **0.7536** |
| CatBoost depth=6 | 0.7533 |

Выбран **CatBoost depth=5**. На отложенном тесте из 7 478 клиентов:

- **ROC-AUC 0.7778**, Average Precision 0.1143.
- `Precision@Top10%` 0.0856, **Recall@Top10% 0.4444**: среди ~10% клиентов с максимальными скорингами находится **64 из 144** будущих покупателей.
- Порог с максимумом F1 на валидации: ~0.0883; Precision / Recall / F1 при нём на тесте ~0.1597.
- Доля положительных клиентов во всём датасете ~1.93%.

Результат зависит от состава исходной базы, пакетов и фиксированного `random_state=42`. Предсказанная высокая склонность к покупке **не означает доказанный инкрементальный эффект рекламы**: для этого нужен A/B-тест или uplift-моделирование.
